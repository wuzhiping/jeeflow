## 4. 修复方法总结

### 4.1 修复 A：改节点 id（推荐，无依赖）
```bash
# 原：节点 id = "review_role"，SPI 无此 role
sed -i 's|"review_role"|"finance"|g' ./your-flow.json
# 或直接在 JSON 编辑器改
```
优点：无需重启服务；缺点：节点 id 命名受限（必须用 SPI 已有的 role_code）

### 4.2 修复 B：加 SPI JSON（适合自定义 role）
```bash
# 1. 备份
cp ./spi/demo/DEMO_ROLE_TO_USERS.json ./spi/demo/DEMO_ROLE_TO_USERS.json.bak

# 2. 修改 SPI JSON（用 jq 或 python）
python3 -c "
import json
with open('./spi/demo/DEMO_ROLE_TO_USERS.json') as f:
    d = json.load(f)
d['custom_role'] = ['userA']
with open('./spi/demo/DEMO_ROLE_TO_USERS.json', 'w') as f:
    json.dump(d, f, indent=2, ensure_ascii=False)
"

# 3. ⚠️ human 重启服务（uvicorn --reload 不监控 JSON）
```

优点：节点 id 任意命名；缺点：需重启服务

### 4.3 推荐：用已有 SPI role（修复 A）

| 已有 SPI role | actors | 适用场景 |
|---|---|---|
| leader | [leader] | 部门组长审批 |
| manager | [manager] | 部门经理审批 |
| director | [director] | 部门总监审批 |
| boss | [boss] | 总经理审批 |
| finance | [leader, manager] | 财务复核 |
| task4 | [userC] | 自定义（已有） |
| boss_audit | [boss] | 总经理审批（Task 5 添加） |
