## 五、严重发现（决策路由失效）

### 5.1 【高危】决策节点 expr 评估失效（两个分支都走第一条出边）

**实测**：
- amount=2000 → decision1 → task2（符合 expr `amount > 1000` 为 true）
- amount=500 → decision1 → task2（**应走 task3** 但走了 task2）

**结论**：引擎**未评估** decision1 的出边 expr，**始终走第一条出边**（e3 → task2）。

**疑似原因**：
1. OGNL root context 不包含 `amount` 变量（amount 仅在 `variables.amount` 子对象下）
2. 决策节点 `properties.expr = "amount > 1000"` 和出边 expr 同时存在，引擎优先取节点 expr 评估但无法解析
3. 引擎对 decision 出边 expr 的支持本身存在限制

**实测 task1.variable 显示**：
```json
{
  "variables": {"submitType":0,"amount":500, ...},
  "submitType": 1
}
```
→ `amount` 确实在 `variables` 子对象下，不在 OGNL root。

**修复建议**（**设计层面**，不改源码）：
- 决策出边 expr 改用 OGNL 路径：`#variables.amount > 1000` 或 `variables.amount > 1000`
- 或：增加一个会签/必经节点把 `amount` 写入 task variable（f_amount）后再决策

**AGENTS.md §7 反模式更新**：应明确"决策出边 expr 引用变量须用 OGNL 完整路径，否则 fallback 第一条边"。

### 5.2 【中危】`highLight.historyNodeNames` 漏掉 end 节点

02-multi-task 中 `historyNodeNames` 包含 `"end"`（5 节点全列），但 03-decision-expr 中**没有 `"end"`**：
- 02-multi-task: `["apply","task1","task2","task3","end"]`
- 03-decision-expr: `["apply","task1","task2","decision1"]`（**缺 end**）

可能是 decision 节点之后的 end 节点不被 highLight 计入，但 task2→end 的边 `e5` 也未列在 historyEdgeNames。

**影响**：客户端高亮流程图时，决策路径可能渲染不完整。

### 5.3 【次要】`highLight.historyEdgeNames` 也漏边

Branch A 历史边：`[e0, e_apply_1, e2]` — 缺 `e3`(decision1→task2) 和 `e5`(task2→end)。

对比 02-multi-task 历史边：`[e0, e_apply_1, e2, e3, e4]` — **全 5 边列出**。

**疑似原因**：决策节点的出边不计入 highLight（仅计入 task 节点之间的边）。
