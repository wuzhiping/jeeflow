### 2.3 用户授权读源码（`engine.py`）

按用户指示读 `venv/lib/python3.12/site-packages/jeeflow/engine.py`：

- `_evaluate_decision` (line 353-375)：先 expr 求值，全 False 则回退取第一条**无 expr**的边，否则取第一条边
- `SimpleExprEvaluator.eval` (`main_pg.py:71-89`)：

```python
m = re.match(r"^\s*(\w+)\s*(>=|<=|!=|==|>|<)\s*(\d+(?:\.\d+)?)\s*$", expr)
if not m: return False     # 格式不匹配直接 False
key, op, val = m.group(1), m.group(2), float(m.group(3))
actual = vars.get(key)      # 直接 vars[key]，**不展开嵌套**
if actual is None: return False
```

**核心约束**：
1. expr 必须严格 `<varname> <op> <number>` 格式
2. 变量必须直接存在于 vars 顶层

### 2.4 根因发现

测试时传 `"amount": 500` 在 `startAndExecute.variables` 内（嵌套），但 `vars_ = {**(args or {})}` 把整个 args 当顶层 vars_，所以 `inst.variables = {"variables": {"amount": 500, ...}, "title": "...", ...}`。`vars_.get("amount")` 返回 None → 所有 expr 返回 False → 兜底走首边。

### 2.5 修复方案 G（成功）

```bash
# ❌ 错误：amount 嵌套在 variables 内
{"variables": {"amount": 500, "submitType": 0}}

# ✅ 正确：amount 放在 startAndExecute 顶层
{"amount": 500, "variables": {"submitType": 0, "u_userId": "applicant", "u_realName": "申请人"}}
```

`flow_args = {k: v for k, v in args.items() if k not in ("processDefineId", "operator")}`（`facade.py:153`）保留所有顶层键，故 `amount` 平铺进入 `inst.variables`。
