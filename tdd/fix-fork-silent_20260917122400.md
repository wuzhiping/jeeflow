## 5. 根因修复建议（待 engine 层）

**当前实现局限**：handler 失败的 fork 分支在 `highLight.historyNodeNames` 中仍显示，**业务上无法靠 detail/activeTaskList 检测**（必须依赖外部 stderr 日志）。

**引擎层修复方案**（不修改 jeeflow，本测试不实施）：
1. fork 节点跟踪"未激活分支"，记录到 `inst.variables._fork_inactive_nodes`
2. join 节点检查此变量，若存在未激活分支 → 拒绝流转，记 error
3. 或：handler 返回 [] 时 fork 主流程记录 warning + 触发 ProcessEvent(type=ERROR)

## 6. 缓解措施

### 6.1 设计时
- fork 分支关键审批节点优先用 `assignee="<user>"` 而非 handler
- 避免在 fork 内使用 handler（handler 失败风险）
- 或 fork 分支前加 decision 显式路由

### 6.2 测试时
- fork 流程**必须**逐分支验证 `activeTaskList` 包含预期 task
- `highLight.historyNodeNames` 含节点 ≠ task 一定创建
- 配合 `tail -f /tmp/jee-fix.log` 实时检测 handler 失败

### 6.3 引擎层（建议）
- fork 节点跟踪未激活分支，join 检查
- handler 失败时 fork 记录 warning + 触发 ERROR 事件
- 提供 API `/wf/processInstance/forkCoverage` 检查 fork 覆盖度
