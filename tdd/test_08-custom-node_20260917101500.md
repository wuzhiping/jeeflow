## 3. 根因分析

### 3.1 引擎处理 custom 节点

`engine.py:324-329`：

```python
async def _execute_node(self, flow, inst, node, operator, vars_):
    if node.type in (TYPE_TASK, TYPE_CUSTOM):
        await self._create_task(node, inst, operator, vars_)
        return
```

**custom 节点与 task 节点共用 `_create_task`**——没有 clazz/methodName 的反射调用逻辑。

### 3.2 _resolve_actors 解析失败

custom1.properties 字段：

```json
{ "clazz": "...", "methodName": "execute", "args": "param1", "val": "customResult" }
```

`engine.py:415-451` `_resolve_actors` 解析顺序：
1. `vars_[KEY_NEXT_NODE_OPERATOR]` — vars_ 无此键
2. `properties.assignee` — custom1 **无此字段**
3. `properties.assignmentHandler` — custom1 **无此字段**
4. `ext.assignment_handler` — main.py 未注册

→ actors = `[]`

### 3.3 _create_task 提前 return

`engine.py:378-379`：

```python
actors = await self._resolve_actors(node, inst, operator, vars_)
if not actors: return
```

actors=[] 直接 return，**不创建 task**。

### 3.4 clazz/methodName 完全未处理

```bash
grep -rn "clazz\|methodName" venv/lib/python3.12/site-packages/jeeflow/
# 0 命中
```

引擎**完全没有**自定义节点反射调用外部类的实现。

## 4. 验证：尝试 tf_nextNodeOperator 变量注入

```bash

实测：

```

**仍卡死**。`tf_nextNodeOperator` 仅在 ROLLBACK 路径（`_sync_resolve_actors`，engine.py:252）有效，**普通流转的 `_resolve_actors`（engine.py:417）也用 vars_ 但 vars_ 中 tf_nextNodeOperator 没传过去**——可能因为 `apply` 执行时 vars_ 不含此 key，或 custom1._resolve_actors 时 vars_ 是 base_vars + task.variables，但 tf_nextNodeOperator 是执行参数级（tf_*），不在 vars_ 顶层。
