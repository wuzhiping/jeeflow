## 4. 关键发现

### 4.1 SubmitType 枚举（实测）

| 值 | 名称 | 语义 |
|---|---|---|
| 0 | APPLY | 申请（startAndExecute 自动注入） |
| 1 | AGREE | 同意 |
| **2** | **REJECT** | **驳回（实例级终止 → state=45）** |
| 3 | ROLLBACK | 回退到上一任务 |
| 4 | JUMP | 跳转到指定任务 |
| 5 | RE_APPLY | 重新申请 |
| 6 | ROLLBACK_TO_OPERATOR | 回退到发起人 |
| 20 | COUNTERSIGN_DISAGREE | 会签软拒绝（不阻断） |

### 4.2 Reject 路径

`engine.py:144-150`：

```python
async def execute_and_jump_to_end(self, task_id, operator, args):
    _, inst, _, _ = await self._prepare_execute_task(task_id, operator, args)
    # 门面 submitType=2 REJECT 唯一入口（对齐 Java executeAndJumpToEnd 语义）
    inst.reject(datetime.now())
    await self.repo.update_instance(inst)
    await self._fire_event(ProcessEvent(EventType.PROCESS_REJECT, inst.id, task_id, operator=operator))
```

`submitType=2` → `execute_and_jump_to_end` → `inst.reject()` → **state=45 REJECT**。

### 4.3 设计意图 vs 实测

| 项 | 设计（文件名） | 实测 JSON |
|---|---|---|
| 名称 | `with-reject` | 同 |
| 节点 | 5 节点串行 | 同 |
| **reject 边** | 暗示有 | **没有**（所有边 properties 空） |
| reject 行为 | 期待驳回到 apply 修改 | **实例级终止**（state=45） |

**驳回到 apply 重新提交需要**：
- 显式 reject 边（`targetNodeId: "apply"`）
- 或用 submitType=3 ROLLBACK（回退到上一任务节点）

当前 JSON 设计为 **"一次性驳回"**（reject 即终止），不回到 apply。
