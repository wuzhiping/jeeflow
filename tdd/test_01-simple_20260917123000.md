## 7. 复盘

### 7.1 新发现：PG 后端 ID 格式

PG 后端 `processDesign.id` 和 `processDefine.id` 是 **雪花 ID**（19 位数字，基于时间戳），与 sqlite 自增 ID（1-17 / 累积 113）格式完全不同。

**影响**：
- runner 不能再依赖硬编码 ID（如 `processDefineId=113`）
- 必须读取 `save`/`deploy` 响应中的 `data.id` 和 `data.processDefineId`
- `getLastByName` 等查询接口也需适配新 ID 格式

**docs 改进**：建议在 `docs/flow.md` §2 或 `docs/AGENTS.md §5.2.5` 补充：
> ⚠️ **PG 后端 ID 格式**：design_id 和 processDefineId 是 19 位雪花 ID（time-ordered），非 sqlite 自增。runner 必须用本轮 deploy 响应的 `processDefineId`。

候选改动待 02 测试后看是否有更多 PG 特定问题，统一更新。
