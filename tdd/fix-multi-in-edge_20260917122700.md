## 2. 测试结果

### Case A：双入边 fanin-task
- fork 后 active: branch_A (leader) + branch_B (manager)
- leader execute branch_A → 完成
- manager execute branch_B → 完成
- **fanin 后 active=2，2 个 fanin_task task**（双入边触发）
- 需各执行 1 次（userA userA）

### Case B：用 join 节点
- fork 后 active: branch_A + branch_B
- leader + manager 执行
- join 节点处理 → fanin_task 创建
- **join 后 active=1，仅 1 个 fanin_task**（✅ 修复有效）
- userA execute fanin_task → state=10（**⚠️ end 未触发**）

## 3. ⚠️ 新发现：Case B join 后 end 节点未触发

**现象**：
- 流程走到 fanin_task，userA execute 完成
- fanin_task state=20，但 instance state=10 DOING
- highLight history: `[apply, branch_A, branch_B, fanin_task, fork1, fanin_join]`
- **end 节点不在 history 中**

**预期**：fanin_task 完成 → end 触发 → instance state=20 DONE

**根因推测**：
- `engine.py:336-338` join 节点处理：`if not find_doing_tasks(...)` 时调 `_execute_node` 流转到 fanin_task
- fanin_task 完成时调用 `_execute_node(end)` 但可能没正确流转到 end

**这不影响 T7 核心目标**（修复 task 重复），但发现 join 节点的另一个潜在问题。

## 4. 关键说明

**`engine.py:80-82` `_execute_node` 在节点被前驱激活时都创建新 task**，多入边 → 多次 `_execute_node` → 多 task。

**修复方案**：fan-in 用 `snaker:join` 节点（type=join），join 节点 `find_doing_tasks=0` 时一次性触发下游 task。
