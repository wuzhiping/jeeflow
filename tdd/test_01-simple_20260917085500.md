## 五、与现有文档的偏差

### 5.1 【关键】AGENTS.md §10 测试 Agent 自检清单错误

AGENTS.md §10 写：
> 走完所有 task，`processInstance/detail` 显示 `state==7`（已完成）

**实测真实情况**：
- `detail.state` 是 **`InstanceState` 枚举值**：`10=DOING / 20=DONE / 30=WITHDRAW / 40=INTERRUPT / 45=REJECT / 50=PENDING / 99=ABANDON`
- `detail.finish_state` 字段存在但**整个生命周期恒为 `null`**，不是已完成标志
- 真正的"已完成" = `detail.state == 20`

→ §10 该条目应改为：`processInstance/detail 显示 state==20（InstanceState.DONE）`

### 5.2 【关键】AGENTS.md §5.2.5 描述不准确

AGENTS.md §5.2.5 说：
> 会清空所有 identity / 实例 / 任务，重载 seed 中的流程定义

**实测**：
- `/api/reset` **不清空 `processDesign` 表**（designId 自增累积）
- `/api/reset` **不清空 `processDefine` 表**（每次 deploy 新增一条 version+1 记录）
- 实测本次复测：seed `simple` v1（id=1）保留；本次 deploy `simple` v2（id=113）

→ §5.2.5 应明确：`processDesign / processDefine` 保留历史版本；reset 后 deploy 会创建**新版本**，不要硬编码 processDefineId。

### 5.3 【重要】AGENTS.md §5.4 示例缺 `assignees` 字段

§5.4 的 `startAndExecute` curl 示例没有 `assignees` 字段。实测不传 `assignees` 时，下游 task 处于 taskState=10 但 operator=空，runner 无法自动推进。

→ §5.4 示例应补充 `assignees: {"<taskName>":"<userId>"}` 字段，并提示"若需要下游 task 自动可被 execute，assignees 必须传"。

### 5.4 【次要】`processTask/execute` 字段命名

实测请求字段是 **`processTaskId`**（不是 §5.5 示例中的 `taskId`）。runner v4 已修正，但 §5.5 示例未更新。

→ §5.5 示例应使用 `processTaskId`。

### 5.5 【次要】`detail` 响应字段说明缺失

`detail.tasks[]` 包含的字段：`id, processInstanceId, taskName, displayName, taskType, performType, taskState, operator, finishTime, expireTime, formKey, taskParentId, variable, createTime, ...`。
其中 `taskState` 是 `TaskState` 枚举：`10=DOING / 20=DONE`。

→ `./docs/state.md` 应补充 TaskState 枚举表。

### 5.6 【次要】`highLight` 响应结构未文档化

`highLight` 返回：
```json
{
  "activeNodeNames": [...],
  "historyNodeNames": [...],
  "historyEdgeNames": [...],
  "nodeProgress": {
    "<nodeName>": { "members": [{"id","name","done"}] }
  }
}
```

→ `./docs/api.md` §highLight 段应补充响应结构。
