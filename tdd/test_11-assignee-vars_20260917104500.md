## 4. 关键发现

### 4.1 assignee 变量解析规则

`engine.py:415-451` `_resolve_actors`：

```python
assignee = node.properties.get("assignee", "")
if assignee:
    actors = []
    for a in assignee.split(","):               # 按逗号拆分
        token = a.strip()
        if not token: continue
        if "applicant" in token:
            token = token.replace("applicant", inst.operator)
        # token 即变量 key：命中用值、未命中字面量
        if token in vars_:
            val = vars_[token]
            if isinstance(val, (list, tuple)):
                actors.extend(str(x) for x in val)
            else:
                actors.append(str(val))
        else:
            actors.append(token)
    return actors
```

**实测行为**：
- 单变量 `assignee="deptLeader"` → `vars_.get("deptLeader")` 命中用值；未命中用字面量
- 多变量 `assignee="userA,userB"` → 拆分后各自查 `vars_`，都未命中 → 都字面量
- 变量值是 list/tuple → 展开为多个 actor

### 4.2 变量 placement 一致性

与 10-mixed-mode 决策 expr 一样，**业务变量必须顶层传入**：

| 写法 | 是否生效 |
|---|---|
| `deptLeader: "userX"` (startAndExecute 顶层) | ✅ |
| `variables: {deptLeader: "userX"}` | ❌ vars_["variables"]["deptLeader"]，不会被 `_resolve_actors` 命中 |

### 4.3 字面量 fallback 实用性

未传变量时 actor=字面量（如 "deptLeader"）：
- 流程能正常推进
- 但执行人字符串（如 "deptLeader"）通常不是真实用户，会卡在 todoList（因为没有该用户）
- **设计建议**：assignee 写变量时，确保 startAndExecute 必传该变量，否则流程卡死
