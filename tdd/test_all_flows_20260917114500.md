## 关键发现

### Runner 设计要点

- **activeTaskList 选择**：当 actor 指定时，按 `taskActorIdList` 包含匹配；否则取 `[0]`
  - 并行会签时 4 个 task1 顺序不一定按 userA/B/C/D 排列，必须按 actor 匹配
- **submitType**：默认 0（AGREE）；13-one-vote-veto 用 20（DISAGREE）；11-assignment-handler 用 1（不传 submitType 也可，0 OK）
- **assignees 必传**：`assignees="<operator>"` 给 startAndExecute 自动执行 apply；不传则 apply 也卡死

### 流程设计注意事项

- **11-assignment-handler**：无 apply 节点，task1 自动跑（FormFieldAssigneeHandler 解析 f_task1=user1）。Runner actor 从 task2 开始
- **14-decision-submitType**：submitType=0 走 end fallback（decision expr `||` 不支持）
- **15-decision-amount**：amount 必须**顶层**（不在 variables 嵌套）。amount<10000 → decision→end（无 task1 actor）；amount>=10000 → decision→task1(user2)
- **07-countersign-ratio**：设计是 2/4 通过（`#nrOfCompletedInstances==2`），不是 3/4

### 已修复的依赖

- `./spi/demo/DEMO_ROLES.json`：+finance +task4
- `./spi/demo/DEMO_ROLE_TO_USERS.json`：+finance:[leader,manager] +task4:[userC]
- `./main.py` + `./main_pg.py`：monkey-patch facade.flow 解包 startAndExecute variables 嵌套（Issue D）

### 已知 FAIL（不可修复，需 engine 改动）

- **08-custom-node**：custom 节点反射未实现（`./docs/known-issues.md §16`）。`engine._create_task` 共用 TYPE_TASK/CUSTOM，**无 clazz/methodName 反射实现**
