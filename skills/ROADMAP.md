# ROADMAP.md · 客户视角的发展规划

> **视角**: 不是"我们想做什么", 而是"客户需要我们做什么".
> **节奏**: 客户反馈驱动规划, 而不是规划驱动开发.
> **冻结约束**: `FREEZE.md` 范围内不主动启动 Phase 1-7 增量工作.

---

## 3. Phase 9 · 客户驱动的改进 (解冻后)

**前置**: `FREEZE.md §4.1` 5 项条件满足.
**目标**: 用反馈驱动修复 + 改进 + 完善, **不**主动造功能.

### 3.1 Phase 9.1 · 反馈 Top-N BUG 修复

**输入**: `skills/feedback/metrics/` 季度统计的 Top-N BUG.
**输出**: `docs/BUGS.md` 新增 FIX-T 编号 + BDD 回归.
**节奏**: 每月修复 P0 BUG 1-3 个, P1 BUG 3-5 个.
**不修**: 不在 Top-N 内的 BUG (即使工程师觉得重要).

### 3.2 Phase 9.2 · 反馈 Top-N 流程模式补齐

**输入**: 客户反馈中"流程无法表达" 的场景 Top-N.
**输出**: 新增 `flows/*.json` (P0/P1/P2) + `docs/flow.md` 章节.
**节奏**: 季度新增 3-5 个高频流程模式.

### 3.3 Phase 9.3 · 反馈 Top-N 文档完善

**输入**: 客户反馈中"文档读不懂" Top-N.
**输出**: `docs/*.md` 修订 + `flow-tutorial.md` 增补.
**节奏**: 持续.

## 7. 决策机制

### 7.1 谁可以提"加项目"

| 来源 | 可提 | 决策 |
|------|------|------|
| 客户反馈 (FB-NNNN, P0/P1) | ✅ | 自动入 Phase 9 候选池 |
| 客户反馈 (P2) | ✅ | 季度评估 |
| 工程师自提 (无反馈支撑) | ✅ | 入 Phase 8.3 候选池, 季度评估 |
| 外部参照 (Camunda 等) | ⚠️ | 需客户反馈佐证 |

### 7.2 谁可以踢项目

| 角色 | 可踢 |
|------|------|
| hermes | 客户反馈类 (无反馈支撑的踢) |
| bro | 引擎风险类 (技术不可行的踢) |
| 双签 | 战略方向类 |
| 客户 | 与自身相关的 (高优先级) |

### 7.3 优先级冲突

| 冲突类型 | 处理 |
|----------|------|
| 客户要 vs 客户要 | 影响面大的优先 (见 `CUSTOMER.md §6`) |
| 客户要 vs 工程成本 | 修复成本 < 3 天 → 做; > 3 天 → 评估替代方案 |
| L1 vs L3 | L3 优先 (见 `CUSTOMER.md §6`) |
| 新功能 vs 修 BUG | 修 BUG 优先 (反馈闭环里 P0 BUG) |

## 8. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 反馈量太少, 无法驱动规划 | 高 | 中 | 主动询问, 制造轻量反馈入口 |
| 反馈质量差, 不可执行 | 中 | 中 | 追问细节, 闭环前确认 |
| 客户沉默, 无回应 | 中 | 中 | 多渠道尝试 + 沉默即归档 |
| 团队理解不一致 | 中 | 高 | 制度化 (SKILL-TREE + RACI) |
| 反馈驱动 vs 工程师惯性冲突 | 高 | 高 | 双签 + 季度复盘 |
| 冻结太久, 团队士气低 | 中 | 中 | 反馈闭环本身就是价值创造 |

## 9. 月度检查点

每月末回答以下问题:

1. 本月收到多少反馈? (按类型, 按优先级)
2. 闭环率多少? SLA 达标率多少?
3. Top-3 痛点是什么? 应对方案?
4. 有没有新增客户档案?
5. 客户旅程实证了多少?
6. 制度漏洞有没有?

写入 `skills/feedback/metrics/YYYY-MM.md`.
