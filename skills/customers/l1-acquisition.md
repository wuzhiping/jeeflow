# L1 引擎客户招揽策略

> **现状**: `customers/index.md` 显示 L1 = 0, 是唯一客户盲区.
> **目的**: 找到至少 1 个 L1 引擎客户 (集成开发者 / 工作流平台搭建方).
> **关联**: `CUSTOMER.md §2.1` + `ROADMAP.md §11.2`.

---

## 1. 什么是 L1 引擎客户

| 维度 | 描述 |
|------|------|
| **身份** | 集成开发者 / 自研工作流系统的工程团队 |
| **直接消费** | jeeflow 提供的 API (38 action + 9 监控端点) |
| **关注** | API 稳定性 / 向后兼容 / 文档完整 / BUG 修复 SLA |
| **数量级** | 通常 < 10, 单客价值高 |
| **沟通方式** | 邮件 / GitHub Issue / 集成群 |

## 2. L1 客户的 4 类典型画像

### 2.1 类型 A · 中型 SaaS 集成方

**场景**: 一个 SaaS 产品想加审批流能力, 不愿自研, 集成 jeeflow

**关注**:
- API 完整度 (能否覆盖他们的场景)
- 性能 (QPS / 延迟)
- 多租户隔离
- 监控 + 告警

**触达渠道**:
- SaaS 开发者社区 (如 SaaS 之家 / IndieHackers)
- 钉钉 / 飞书 开发者群

**推销话术**:
> 我们 jeeflow 是一个轻量级工作流引擎, 单二进制部署, 双后端 (内存 / PG),
> 38 个 action + 9 个监控端点, OpenAPI 3.1 规范.
> 如果你们在做审批 / 流程类功能, 可以快速集成, 比从零自研省 3-6 个月.

---

### 2.2 类型 B · 企业内部 IT / 数字化团队

**场景**: 大企业 IT 团队想统一各业务线的审批流

**关注**:
- 安全 / 合规 / 等保
- 高可用 / 灾备
- 与现有 ERP / OA 集成
- 权限模型

**触达渠道**:
- CIO 圈子 / IT 行业会议
- 微信公众号 (如 "企业数字化")
- 行业咨询公司

**推销话术**:
> jeeflow 支持私有化部署, 双后端 (PG 生产级), 9 个监控端点,
> trace_id 全链路追踪, 已通过内部 SLA 验证 (43/43 项).
> 如果你们在做内部审批流统一, 可以快速 POC.

---

### 2.3 类型 C · 工作流产品公司

**场景**: 一个做工作流 / BPM 的公司, 想在底层引擎上自建产品

**关注**:
- 引擎扩展性 (handler / interceptor / 自定义节点)
- 商业授权 / 价格
- 技术支持

**触达渠道**:
- 工作流 / BPM 社区
- Camunda / Flowable 用户群 (迁移需求)
- GitHub BPM 相关项目

**推销话术**:
> jeeflow 是基于 Snaker 引擎的 Python 改写, 全部 Python 栈,
> 易二次开发. 支持 6 种节点 + 4 种会签模式 + 自定义节点 handler.
> 如果你们在 Camunda / Flowable 之外寻找更轻的替代, 可以对比.

---

### 2.4 类型 D · 教育 / 培训用户

**场景**: 大学 / 培训机构教工作流原理, 找教学用引擎

**关注**:
- 代码可读性
- 文档 / 教学材料
- 免费 / 低成本

**触达渠道**:
- 大学计算机系
- 在线教育平台 (慕课网 / Coursera)
- GitHub

**推销话术**:
> jeeflow 是开源友好的私用项目, 代码 ~5K 行,
> 含完整 BDD 测试 + 文档 + 客户反馈闭环.
> 适合作为工作流引擎教学案例.

## 3. 招揽 7 步流程

### Step 1 · 画像锁定 (1 天)

回答:
- 我们要哪类 L1? (A/B/C/D)
- 触达渠道是什么?
- 价值主张 1 句话?

### Step 2 · 渠道铺设 (3-7 天)

按选定渠道:
- 加入社区 / 群 / 邮件列表
- 关注潜在客户的提问
- 不要立即推销, 先建立存在感

### Step 3 · 软接触 (持续)

- 回答社区问题
- 分享 jeeflow 实践经验 (如本次反馈闭环)
- 让对方知道"这个团队靠谱"

### Step 4 · 识别信号

**强信号** (高意向):
- 对方主动问"jeeflow 怎么集成"
- 对方提"我们正在评估工作流引擎"
- 对方在 Camunda / Flowable 群问替代品

**弱信号** (需培育):
- 点赞 / 收藏
- 一般性提问
- 关注但不互动

### Step 5 · 首次对话

提供:
- 1 页产品介绍
- 5 分钟集成 demo
- OpenAPI 链接
- 公开 BDD 演示

### Step 6 · POC

- 给对方 sandbox 环境 (我们的 memory backend)
- 协助跑通 1 个真实流程
- 收集反馈 (走 FB 闭环)

### Step 7 · 转 L1 客户

- 对方决定集成 → 创建 C-NNN.yaml (L1)
- 持续跟踪 → 进 RACI 矩阵
- 形成参考案例

## 5. 不做的事 (避免过度推销)

| 反模式 | 为什么错 |
|--------|----------|
| 群发广告 | 社区反感, 适得其反 |
| 假装客户提问 | 一旦被发现, 信任崩塌 |
| 承诺做不到的能力 | 客户实测后失望, 不可逆 |
| 不走反馈闭环就推销 | 失去质量口碑 |
| 频繁打扰 (3 天 / 次) | 对方拉黑 |

## 6. 衡量指标

| 指标 | 含义 | 目标 |
|------|------|------|
| L1 客户数 | 已建档 L1 客户 | ≥ 1 (季度) |

| POC 完成率 | 对话 → POC | > 30% |
| 集成完成率 | POC → 集成 | > 50% |
| FB 数 (L1) | L1 客户反馈条数 | ≥ 1 / 季度 |
