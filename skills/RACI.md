---

## 1. RACI 速记

| 字母 | 含义 | 一句话 |
|------|------|--------|
| R | Responsible | **做**这件事的人 |
| A | Accountable | **担责**的人 (每件事只有 1 个 A) |
| C | Consulted | **咨询**前要问的人 |
| I | Informed | **事后**被告知的人 |

**铁律**: 每件事只能有 1 个 A. R 可以多个. C / I 按需.

## 4. 反馈闭环专项 RACI (核心子矩阵)

> `FEEDBACK.md` §3 的 5 步流程, 这里明确谁 R 谁 A.

| 步骤 | 主要 R | 主要 A | 协作 C | 通知 I |
|------|--------|--------|--------|--------|
| **01 接收** | CLI | CLI | PROC, ENGD | — |
| **02 分类** | CLI | CLI | PROC, ENGD | 客户 |
| **03 处理 (engine)** | ENGD | ENGD | PROC, ENGT, CLI | 客户 |
| **03 处理 (flow)** | PROC | PROC | ENGD, PROCT, CLI | 客户 |
| **03 处理 (doc)** | PROC | PROC | ENGD, CLI | 客户 |
| **03 处理 (UX)** | INTEG | INTEG | PROC, CLI | 客户 |
| **03 处理 (consult)** | CLI | CLI | PROC, ENGD | 客户 |
| **04 内部验证** | ENGD + PROC | CLI | ENGT, PROCT | 客户 |
| **04 客户回访** | CLI | CLI | PROC, ENGD | 客户 |
| **05 通知** | CLI | CLI | PROC, ENGD | 全团队 |
| **沉淀** | ENGD (engine) + PROC (flow+doc) | CLI | — | 全团队 |

**关键点**:
- CLI 是**总 A** (问责), 不一定是每个步骤的执行者
- 跨类型协作必须明确谁是该步骤的 R
- 客户永远是 I (被通知)

## 5. 跨活动冲突处理

| 冲突类型 | 谁仲裁 |
|----------|--------|
| ENGD vs PROC (代码 vs 流程) | CLI 仲裁, ARCH 咨询 |
| ENGD vs SRE (功能 vs 稳定) | ARCH 仲裁 |
| PROC vs CLI (设计师 vs 接口人) | 双签 |
| 客户要 A, 工程只想 B | CLI + ENGD 双签, 必要时 ARCH 介入 |
| L1 客户 vs L3 客户 | CLI 仲裁, 按 `CUSTOMER.md §6` 优先级 |
| 反馈量太大 | ENGD 申请解冻, CLI + ENGD 双签 |

## 7. RACI 矩阵的日常使用

### 7.1 任何新活动出现时

回答 3 个问题:
1. 谁 R (做)?
2. 谁 A (担责)?
3. 谁 C / I (咨询 / 通知)?

填入对应单元格. 写入本文件 §3.

### 7.2 冲突出现时

1. 先查本矩阵
2. 矩阵没写 → 双签 (PROC + ENGD)
3. 双签无法解决 → ARCH 仲裁
4. 仍无法解决 → 客户决定 (L3 优先)

### 7.3 矩阵更新条件

- 新增角色 (如 +D 客户接口人)
- 新增活动域
- 角色合并 / 拆分
- 优先级变化

每次更新必须有变更记录, 写入本文档末尾.
