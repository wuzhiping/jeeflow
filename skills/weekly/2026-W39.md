## 🔒 重要提醒 (2026-09-21 记录)

**事件 1**: 用户提醒 · 用户与开发环境不在同一台机器, 用户实例 = https://abc.feg.cn/jeeflow/

**学到**:
- 用户实例是真实工作内容, 不是测试沙盒
- 内存版本重启即丢, 但**不能加速这个过程**
- 任何 reset 相关 API 调用 = 数据丢失 = 信任崩塌

**已落实**:
- `FREEZE.md §6.2` 加入硬约束 (最高优先级)
- `users.md` 顶部加 reset 限制警告
- 本周报作为提醒存档

**事件 2 (同日)**: 首次完成 `users.md` 任务 (与 flowuser 真实对话)

**学到**:
- `hermes peer dm flowuser "..."` 通道工作, 客户响应详细 (94 行)
- **取件码机制验证成功**: 客户给每个文件起短码, 我们按需逐个索取
- **多轮小问比一次性轰炸更有效**: 第一次问太宽, 改进后问"现象+步骤+实例+文件取件码", 客户立刻给出 5 个文件取件码
- **身份要明确**: 我们是 hermes 助理, 不冒充 bro
- **收到确认很重要**: 客户主动反哺 FB-0008 (countersignCompletionCondition 文档缺失)

**已落实**:
- 创建 FB-0007 (BUG-2 真 BUG / P0)
- 创建 FB-0008 (文档缺失 / P1)
- 复盘文档: `skills/feedback/retrospectives/2026-09-21-users-md-task.md`
- users.md 话术升级 (推荐模板 + 工具说明)

**下周起新规则**:
