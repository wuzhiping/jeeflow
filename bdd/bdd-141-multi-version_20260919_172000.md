## 🐛 BUG 发现

### Bug: `processDesign/save` 不按 name UPSERT

**位置**：`vendor/jeeflow/facade.py:_processDesign_save:465-500`

**代码**：
```python
async def _processDesign_save(self, args: dict) -> dict:
    ...
    design_id = self._to_int(args.get("id"))
    if not design_id:
        # 总是创建新 design，没有按 name 查重
        design = ProcessDesign(name=str(args.get("name", "")), ...)
        await ext.save_design(design)
    else:
        # 仅当 id 明确给出时才更新
        ...
```

**现象**：连续 2 次 `processDesign/save`（相同 name，无 id）→ 创建 2 个不同 designId，processDesignHis 分散记录。

**影响**：
- v2 看不到 v1 的历史（his 只记当前 design 的快照）
- 同一流程的版本演进被拆成多个 design 记录
- 部署时按 `list_design_his(design_id)[0]` 取最新 → 多 design 下管理混乱
- 与 AGENTS.md §5.3 描述的"UPSERT by name"不符（实测是 INSERT-only）

**建议修复（FIX-T42）**：
```python
if not design_id:
    # FIX-T42: 按 name 查重，命中则复用 id（UPSERT 语义）
    name = str(args.get("name", ""))
    if name:
        existing = await ext.find_design_by_name(name)
        if existing:
            design_id = existing.id
    if not design_id:
        design = ProcessDesign(name=name, ...)
        await ext.save_design(design)
    else:
        design = await ext.find_design_by_id(design_id)
        # 走更新路径
        ...
```

需要：
1. `ext.find_design_by_name(name)` 端点（memory + jdbc 各加一个）
2. facade 按 name 查重逻辑
3. processDesignHis/processDefine 关联保持单一 designId

**临时绕行**：调用方必须**先 processDesign/page 取 id，再 save(id=xxx) 更新**。
