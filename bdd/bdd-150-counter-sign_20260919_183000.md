# BDD #150 加签/减签 + 变量传递 (20260919 183000)

## 流程设计

```mermaid
flowchart TD
    start([开始]) --> apply[申请人]
    apply --> leader[组长]
    leader --> manager[经理]
    manager --> boss[总经理]
    boss --> end([结束])
```

## 测试场景
- **Case 1**: addCandidate 加签 director → 任意 actor 完成即推进
- **Case 2**: 减签最后一个 actor → 应被拦截（修复后）

## 测试结果

### Case 1: addCandidate 跨角色
| 步骤 | 操作 | 状态 |
|------|------|------|
| 1 | leader_review DOING | leader actorIds=["leader"] |
| 2 | addCandidate actorIds=["director"] | leader_review actorIds=["leader", "director"] ✓ |
| 3 | director 同意 | leader_review state=20 DONE ✓ |
| 4 | 流程推进 | manager_review DOING ✓ |

### Case 2: 减签最后一个 actor (BUG #150)

**修复前**：
```
remove self: {"code":0,"msg":"成功","data":null}
manager_review state=10 actor=None
```
- task state=10 DOING 但 actorIds=空
- 无人可办，流程卡死

**修复后（FIX-T48 2026-09-19）**：
```
remove self: {"code":99999999,"msg":"[ValueError] 减签后 task[xxx] 已无 actor..."}
```

## 🐛 BUG #150 + 修复

### Bug: remove_task_actor 不校验结果
- 位置：`vendor/jeeflow/repository/memory.py:remove_task_actor`
- 现象：减签可把最后 actor 删掉，task 变"无主 DOING"
- 影响：流程卡死，无人可办，前端无法推进

### 修复（FIX-T48 2026-09-19）
- `vendor/jeeflow/memory.py:remove_task_actor` 后检查 `_actors.get(task_id)`
- `vendor/jeeflow/repository/base.py:remove_task_actor` 同样保护（PG 后端）
- 空时 raise `ValueError`，客户端需先 addCandidate 或 abandon task

## API 字段名注意
- addCandidate 字段是 **`actorIds`**（不是 `addActors`）
- removeCandidate 字段是 **`actorIds`**

- pg (8102): 同步修复（base.py）
