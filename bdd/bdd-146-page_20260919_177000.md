## 测试结果

### 分页参数兼容性
| 入参字段 | 引擎接受 | 备注 |
|---------|---------|------|
| `pageNum` (推荐) | ✓ | 文档标准字段 |
| `pageNo` (历史别名) | ❌ | **被忽略，fallback 默认 pageNum=1** |

实测对比：
- `{"pageNo":99,"pageSize":10}` → 响应 `pageNum: 1, pageSize: 10`（fallback 默认）
- `{"pageNum":99,"pageSize":10}` → 响应 `pageNum: 99, pageSize: 10, rows: 0`（越界正确）

### 分页边界
| 场景 | 期望 | 实测 | 结论 |

| pageNum=99, size=10 (越界 35) | rows=0 | ✓ | ✅ |

## 🐛 BUG 发现 + 修复（FIX-T45 2026-09-19）

### Bug: processInstance/page 不识别 `pageNo` 字段
- 位置：`vendor/jeeflow/facade.py:101-107` `_processInstance_page`
- 现象：客户端发 `pageNo=99` → 服务端忽略 → 用默认 `pageNum=1`
- 原因：代码只读 `args.get("pageNum")`，没兼容 `pageNo`
- 影响：客户端（设计器）传 `pageNo` 时**永远拿第一页**，越界判断失效

### 修复（FIX-T45 2026-09-19）

**位置**：`vendor/jeeflow/facade.py` 10 处 `pageNum` 解析

**代码**：
```python
# 修复前
page_num = self._to_int(args.get("pageNum")) or 1
# 修复后
page_num = self._to_int(args.get("pageNum") or args.get("pageNo")) or 1
```

**批处理脚本**：
```python
import re
src = open('vendor/jeeflow/facade.py').read()
src = src.replace(
    'self._to_int(args.get("pageNum"))',
    'self._to_int(args.get("pageNum") or args.get("pageNo"))'
)
open('vendor/jeeflow/facade.py', 'w').write(src)
```
