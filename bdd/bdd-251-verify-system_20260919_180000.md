# BDD #251 verify 规则系统 (20260919 180000)

## 目标
把所有 BDD 狩猎中累积的 BUG / 限制 / 反模式 / 已知问题，沉淀到 `processDesign/save` / `update` / `updateDefine` / `redeploy` / `deploy` 入口的 verify 阶段，**防止错误流程进入运行**。

## 规则集

### Errors (E001-E011) - 阻塞 save

| ID | 规则 | 来源 |
|----|------|------|
| E001 | name 字段缺失或为空 | 现有 |
| E002 | 节点 id 重复 | FIX-T31 |
| E003 | 节点 id 含非法字符 (非 `^[A-Za-z0-9_]+$`) | FIX-T34 |
| E004 | 流程含环 (cycle) | FIX-T50 (BDD #209/213) |
| E005 | 无 start 节点 | BDD #210 |
| E006 | 无 end 节点 | BDD #211 |
| E007 | 边 source/target 引用不存在节点 | BDD #239 |
| E008 | performType=1 但无 countersignType | BDD #214 |
| E009 | 会签节点配 assignmentHandler | 反模式 (会签 assignee 应是字面量列表) |
| E010 | decision 节点无出边 (卡死) | BDD #215 |
| E011 | task 节点无 assignee 也无 assignmentHandler (没人能办) | BDD #159 |

### Warnings (W001-W008) - 不阻塞, 仅记录

| ID | 规则 | 来源 |
|----|------|------|
| W001 | start 节点有入边 (反模式) | 设计原则 |
| W002 | end 节点有出边 (反模式) | 设计原则 |
| W003 | decision 节点所有出边 expr 都为空 (只走兜底) | BDD #155 |
| W004 | 会签节点用 applicant 关键字 | 不合理 |
| W005 | fork 节点无 join 节点对应 | BDD #184 |
| W006 | 流程节点数 > 50 (建议拆分) | 性能 |
| W007 | field 权限声明了但 variables 没用 | 死配置 |
| W008 | 同一对节点重复多条边 (冗余) | 设计原则 |

### Patterns (P001-P004) - 反模式建议

| ID | 规则 |
|----|------|
| P001 | 会签只有 1 个 actor (退化为普通 task) |
| P002 | submitType=4 (JUMP) 但缺 targetTaskName/taskName 字段 |
| P003 | 流程无 task 节点 (纯计算, 注意 'type=business' 才能纯计算) |
| P004 | decision 嵌套深度 > 3 (可读性差) |

## 实现

### 1. 新增模块
- **`vendor/jeeflow/verify.py`** (294 行)
  - `verify_flow(flow, variables) -> (errors, warnings, patterns)`
  - `format_issues(issues) -> str`
  - 集中所有规则 + DFS 环检测
  - 同步到 `.venv/lib/python3.12/site-packages/jeeflow/verify.py`

### 2. 接入入口
- `JeeflowFacade._verify_or_raise(content, args, variables=None)` (facade.py:253)
- 集成到 6 个入口：
  - `_processDesign_save` - save 设计时
  - `_processDesign_update` - update 设计基本信息
  - `_processDesign_updateDefine` - 更新定义
  - `_processDesign_redeploy` - 重新部署
  - `_deploy` - 直接 deploy
  - `_processDesign_deploy` - 通过 design deploy (走 _deploy)

### 3. skipVerify 开关
- 请求 body 含 `"skipVerify": true` 时**只 warn 不 raise**
- 用途：开发测试新功能 / 测已知的引擎 BUG
- 不影响数据写入, 只跳过校验
