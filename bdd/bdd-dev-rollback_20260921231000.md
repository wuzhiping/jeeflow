# BDD-DEV-013 dev-rollback (20260921231000)

## 流程设计

```mermaid
flowchart LR
    start([开始]) --> apply[提交请假]
    apply --> leader_approve[组长审批<br/>u_fe_lead]
    leader_approve --> hr_approve[HR 审批<br/>u_rd_dir]
    hr_approve --> end([结束])
```

## 场景

请假流程 - submitType=3 (ROLLBACK) 回滚测试。HR 驳回后流程回到 leader_approve。

## 用到的能力

- `submitType=3` (ROLLBACK) + `taskName` 指定回滚目标
- 任务重激活：原 `leader_approve` task 新建 DOING，actorIds 保留原 assignee
- 流程继续推进：u_fe_lead → 再次 approve → hr_approve → end

## BUG 发现与修复

### ~~BUG-5 (FIX-T114) ROLLBACK 后原 assignee 丢失~~
- **现象**: HR (u_rd_dir) 提交 submitType=3 回滚到 leader_approve 后，u_fe_lead 待办 = 0 而 u_rd_dir = 1
- **初判**: 引擎代码 `engine.py:258` 在 `if not target_task_name` 分支覆写 `prev.properties.assignee = task.actorId or operator`，导致原 assignee 丢失
- **实际根因**: 用户测试时把 `taskName` 放在 `variables` 内（按 docs/AGENTS.md §5.5 范例），但 Facade `facade.py:737` 只读顶层 `args.get("taskName")`。所以 `target=""` 走了"无 target"分支触发 FIX-T36 §52 行为。
- **修复**: `vendor/jeeflow/facade.py:737/741` 同时兼容 `args.taskName` / `args.targetTaskName` / `args.variables.taskName` / `args.variables.targetTaskName`。
- **验证**: 修复后两种姿势（顶层 + variables 内）都正确路由到目标节点，u_fe_lead 待办正确出现。

### 设计陷阱 (FIX-T36 §52 行为)
- **submitType=3 不带 taskName** 时：引擎查找上一个任务节点，**覆写 assignee** = `前任务完成人 or 操作人`
- **场景**: HR (u_rd_dir) 撤回 → 上一个 task 是 leader_approve (assignee=u_fe_lead) → 覆写为 u_rd_dir (前任务完成人=hr_approve 完成人=u_rd_dir)
- **设计意图** (Java rejectTask): rejecter 期望自己能重做前一步
- **实际效果**: 原 assignee 失去 re-process 能力
- **建议**: 设计师若想保留原 assignee, **必须显式传 taskName**
