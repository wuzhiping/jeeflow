## 设计陷阱（已知）

- 原 flow **无 apply 节点**（start→task1 直接接）
- `startAndExecute` 自动完成第一个 DOING task (task1)，operator 被 add_task_actor 加入 task1
- 这是原 flow 的设计意图（4 handler 演示），非 bug
- `flows_dev` 适配保持原状未改动

## 排查过程（FIX-T115 debug）

引擎 `startAndExecute` 路径：
```python
doing = await self._repo.find_doing_tasks(inst.id)
for task in doing:  # snapshot
    await self._repo.add_task_actor(task.id, [operator])  # ← 注入 operator
    await self._engine.execute_process_task(task.id, operator, flow_args)
```

针对 `flows/11-assignment-handler.json`（无 apply），doing 列表在 start_process_instance_by_id 后只剩 task1。
`add_task_actor(task1, [operator])` 后 task1 的 actorIds 含 operator，可被自动完成。
FormFieldAssigneeHandler 返回 `['u_qa_lead']`，最终 task1.actorIds = `['u_qa_lead', operator]`，可由任意一方完成。

调试发现不影响流程运转（state=20 DONE），仅演示路径有差异。
