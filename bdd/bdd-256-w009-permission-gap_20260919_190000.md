# BDD #256: W009 字段权限间隙规则 + 引擎 BUG 复现

**时间**: 2026-09-19 19:00
**状态**: ✅ PASS (verify 拦截) + ⚠️ BUG 复现 (运行时未拦截)

## 背景

BDD #256 发现一个新 BUG：**字段在某节点声明 hidden/read，但其他节点未声明时，下游节点可以覆盖该字段**。

引擎默认行为："未声明即可写"，这与 hidden/read 权限的"防护"意图冲突。

## 解决方案：W009 警告规则

新增 W009 规则（`vendor/jeeflow/verify.py:check_permission_gap`）：

| 规则 | 描述 |
|------|------|
| W009 | 字段在某节点声明为 hidden/read，但其他节点未声明 |

**触发示例**：
- `apply` 节点：`field: {PERMISSION_f_secret: 1}` (hidden)
- `leader` 节点：无 f_secret 权限声明
- → W009 警告：建议在 leader 也显式声明 hidden

## 测试结果

### 1. verify 拦截 ✅
```
POST /wf/verify
请求: {name: "w009-gap-test", ...}
响应: {
  valid: true,
  warnings: [{
    code: "W009",
    message: "字段 f_secret 在节点 ['apply'] 声明为 read/hidden, 但节点 ['leader'] 未声明"
  }]
}
```

### 2. deploy 允许（W009 警告不阻塞）✅
```
POST /wf/processDesign/save → 200, code=0
```

### 3. 运行时 BUG 复现 ⚠️
```
1. start: f_secret='TOP_SECRET'
2. userA agree apply: vars={f_secret: 'TOP_SECRET'}
3. userB agree leader: vars={f_secret: 'OVERWRITTEN'} ← 覆盖成功
4. final: f_secret='OVERWRITTEN' ❌
```

**期望**: f_secret 保持 TOP_SECRET（apply hidden）  
**实际**: f_secret='OVERWRITTEN'（userB 覆盖成功）

## 结论

- ✅ **verify 规则 W009 成功阻止新增"有间隙"的流程**
- ⚠️ **运行时未拦截**（Snaker 引擎默认行为，"未声明即可写"）
- ✅ **W009 警告会出现在 design-time verify，让开发者在部署前显式声明所有节点的权限**
