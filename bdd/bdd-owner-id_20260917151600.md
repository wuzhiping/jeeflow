# BDD Task 56: ownerId 与 operator 关系（边界发现）

- **时间**：2026-09-17 15:16:00（TS=20260917151600）

## 1. 测试场景

启动时传 `operator=user1` + `ownerId=userB`，期望 ownerId 字段被识别。

## 2. 实测

```json
{
  "processDefineId": 1,
  "operator": "user1",
  "ownerId": "userB",
  ...
}
```

### 结果

| 字段 | 值 |
|---|---|
| instance.operator | user1 |
| instance.ownerId | **None**（字段不存在） |
| instance.createUser | user1 |
| variables.u_userId | user1 |
| variables.ownerId | userB（被当作普通变量） |
| variables.u_deptId | D01 |

### 关键发现（§66）

1. **`ownerId` 没有独立字段**：facade.startAndExecute 不提取 ownerId 到 ProcessInstance
2. **`ownerId` 仅作为普通变量存入**：variables.ownerId = userB
3. **m_ownerId 过滤不生效**：page 接口未实现 ownerId 字段过滤
4. **processInstance/page 顶层 ownerId 参数不生效**：与 m_operator 一样需走 m_query

### Engine 行为

```python
# facade startAndExecute / facade.py
args["submitType"] = SUBMIT_APPLY  # only this special handling
inst = await self._engine.start_process_instance_by_id(define.id, operator, args)
# ownerId 仅作为 args 一部分 → inst.variables.ownerId
```

### 设计器 vs Java

- Java 设计器有 ownerId 字段（业务所有人）
- Python 引擎 ProcessInstance 模型无 ownerId 字段
- 此为兼容性 gap

## 3. 实际场景

- "代他人发起"场景：operator=userA 替 userB 提交
- 当前实现：instance.operator=userA, but variables.u_userId=userA（userB 信息丢失）
- userB 完全无法查询这个 instance（除非通过 ccList）

## 4. 测试报告

- ownerId 在 Python 引擎**不可用**
- 需要前端/调用方把 ownerId 拼到 u_userId 或 ccList
