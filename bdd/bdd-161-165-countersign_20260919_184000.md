## BDD #164 详细分析

按 docs/known-issues §91 设计意图：
- **PARALLEL + ALL + submitType=20** = **软拒绝**
- userA 拒绝后，自己 task state=20 DONE
- userB/C 仍 DOING，可继续办
- 全部办完后流程 state=20 DONE（**忽视 userA 拒绝**）

**业务影响**：
- 若业务方想"任意人 reject 即失败"，**必须**配 `countersignCompletionCondition: "ONE_VOTE_VETO"`
- 否则默认行为是"软拒绝"（与 Java mldong 内置引擎一致）

**实际验证**：
```bash
userA reject (submitType=20) → userA task DONE
userB approve (submitType=0) → userB task DONE
userC approve (submitType=0) → userC task DONE
state → 20 DONE  # 即便 userA 拒绝了
```
