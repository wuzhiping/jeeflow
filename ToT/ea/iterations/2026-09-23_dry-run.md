## 2. 设计

### 2.1 两种模式
| 模式 | 触发 | 耗时 | 用途 |
|------|------|------|------|
| **dry-run** | `--dry-run` | ~0.16s | CI PR 快速检查 / PR 阶段 |
| **实跑** | 默认 | ~0.85s | 合并前 / 发布前完整回归 |

### 2.2 短路逻辑
```python
# 静态校验 + verify_flow 仍然完整跑（保证 sanity check）
# 跳过：deploy / startAndExecute / execute / inspect（耗时的引擎实跑）
if args.dry_run:
    log("🏃 dry-run 模式：跳过实跑引擎")
    # 生成干跑 md + json 报告
    return 0  # PASS
```

### 2.3 错误检测
- ❌ 静态校验 errors（schema 错误）
- ❌ verify_flow errors（语义错误）
- ✅ 都通过 → DRY-RUN PASSED

## 3. 使用方式

### 3.1 CI PR 阶段（快速）
```bash
# PR check（只检查静态 + 语义，不实跑）
./ToT/bin/jf python3 ToT/sop/tdd-flow.py ToT/flows/<flow>.json --dry-run
```

### 3.2 合并前完整回归
```bash
# 全流程实跑 + baseline 对比
./ToT/bin/jf python3 ToT/sop/tdd-flow.py ToT/flows/<flow>.json \
    --tests-file ToT/tdd/tests.json
```

### 3.3 CI 两阶段
```yaml
# Stage 1 (PR): dry-run
- name: tdd-dry-run
  run: ./ToT/bin/jf python3 ToT/sop/tdd-flow.py ToT/flows/<flow>.json --dry-run

# Stage 2 (merge to main): full run
- name: tdd-full
  run: ./ToT/bin/jf python3 ToT/sop/tdd-flow.py ToT/flows/<flow>.json --tests-file ToT/tdd/tests.json
```

## 7. 经验沉淀

### 7.1 dry-run vs 实跑选择
| 场景 | 推荐模式 |
|------|----------|
| PR check / 提交流 | dry-run |
| commit hook | dry-run |
| merge to main | 实跑 |
| release tag | 实跑 + compare-baseline |
| baseline 重生成 | save-baseline |

### 7.2 dry-run 仍做的事
- ✅ JSON schema 校验
- ✅ 节点/边/类型校验
- ✅ decision expr 语法校验
- ✅ verify_flow 的 patterns 检测
- ❌ 不做：实例创建、execute、task routing

### 7.3 dry-run 的限制
- 不能检测运行时错误（如 cast 时 substring bug）
- 不能检测 actor 解析问题
- 不能验证 baseline 一致性
- → 实跑仍必要
